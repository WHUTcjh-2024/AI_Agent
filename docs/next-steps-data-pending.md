## 2. 数据到位前的执行顺序

### 第一项：Phase 13A — 可重复运行的工程评测

**已实现（2026-09-03）：**运行入口为 `./scripts/eval.ps1`，交付与联调说明见 [Phase 13A](phase-13a-engineering-evaluation.md)。以下保留本阶段验收要求。

优先把现有种子问题和 Phase 12 联调矩阵变成可执行回归，为后续数据接入提供同一套验收入口。

- 增加评测入口、用例结构和 JSON/Markdown 报告，记录代码版本、配置、Provider、知识版本与执行时间。
- 区分离线固定 Evidence 回归与真实服务评测。固定样本只用于测试，不能进入正式知识库或作为校园准确率数据。
- 覆盖稳定知识、时效混合检索、知识能力关闭/失败、Web 超时/零结果、非官方来源、无映射、未审核资料及引用一致性。
- 自动检查路由、降级标记、终态、Source/Citation、缓存行为；补充 SSE 重连、取消、幂等和失败恢复的集成验收。引用是否支持结论保留人工核验项。
- 数据未到位的知识准确率用例标记为 `blocked_data`，报告同时展示通过、失败、跳过/阻塞数量；不能把跳过计为通过。
- 先在 CI 执行无需外部凭证的确定性回归，真实 Provider 评测单独触发并限定调用预算。

**验收：**一条命令生成可追溯报告；预期路由或来源规则被破坏时返回失败退出码；知识库关闭仍能验证工程链路，并明确列出待数据验收项。

### 第二项：Phase 10B — 最小内部 Admin 页面

**已实现（2026-09-03）：**独立控制台、服务端凭证代理、日期筛选及指标展示均已交付，自动联调覆盖问答后指标变化与鉴权边界。运行和验收说明见 [Phase 10B](phase-10b-admin-console.md)。以下保留本阶段验收要求。

基于现有 OpenAPI 和 Admin API 建设 `apps/admin`，先完成试点需要的查看能力。

- 支持日期筛选，展示用户/活跃、问题量、失败与无引用回答、TTFT/总延迟、Token/成本、缓存命中及路由分布。
- 提供 Top Questions、错误码和逐日趋势；标明统计时间窗、时区及留存可计算样本数。
- 处理空数据、加载失败、鉴权失败；样本不足时展示原因，避免把“无样本”呈现为有效留存结论。
- 普通用户凭证不能访问；Admin Token 不写入前端源码、构建产物或移动端。页面的鉴权接入与部署方式随实现一并明确。

**验收：**完成一次测试提问后能看到对应指标变化；空库页面正常；错误凭证与普通用户凭证均无法读取管理数据；指标与 API 返回一致。

### 第三项：补齐原方案 Phase 2 — 真实账号与试点成本边界

这部分不依赖知识数据。所需外部配置可以提前准备，代码与契约工作无需等待。

- 后端通过独立微信 Provider 交换授权结果、关联服务端用户，复用现有 Access/Refresh Token 生命周期；同步更新 OpenAPI。
- 移动端补齐登录、取消、失败、过期重新授权和退出流程，将敏感 Token 迁入系统安全存储并清理旧缓存。
- 正式模式关闭开发登录；验证不同账号数据隔离、同一账号跨设备历史恢复。
- 在现有每分钟限流与 Usage 记录之上，补充可配置的用户日额度和试点总预算策略，覆盖并发、幂等重试、失败与取消的计费边界。

**外部依赖：**微信开放平台 AppID、服务端 Secret、包名、签名及开放平台配置。凭证通过部署环境注入。

**验收：**真机完成微信登录、刷新、退出、重新登录和历史恢复；额度耗尽时不启动新的付费调用。缺少真实配置时，只标记代码/测试准备完成，真实登录验收保持待办。

### 第四项：Android 试点包与运行准备

- 固化 HTTPS API 地址、发布环境配置与签名构建流程，确保开发凭证和 Mock 模式不会进入正式分发配置。
- 按原方案完成多轮、停止、重新生成、复制、分享、来源跳转、历史删除/清空以及弱网恢复的真机验收。
- 为后端准备最小部署、数据库备份恢复、配置回滚与故障排查说明。

**验收：**受控签名 APK 可安装；在目标后端上通过完整流程；失败可定位、版本可回退。数据未验收时仍属于工程联调版本。

## 3. 与合作伙伴并行的数据交付

合作伙伴继续采集和整理；主工程沿用现有契约，准备批次校验、报告和导入工具，不重新开展一套采集任务。

每个交付批次至少包含：

- 批次 ID、来源与数量清单、校验摘要、采集时间、审核与异常统计。
- 符合 Taxonomy 的文档元数据，公开官方 URL、发布时间/有效期及版本关系。
- 网页与附件组成的 Knowledge Bundle，附件关联可追溯。
- 实际执行的 PII 检测记录、人工审核结论与重复内容处理结果。
- Staging 数据、稳定 AskU ID；导入时生成并核验 WeKnora ID 映射。

Canary 的先决条件与枚举映射以 [数据交付与准入](workbuddy-data-handoff.md) 为准。当前本地联调环境使用 `ASKU_KNOWLEDGE_PROVIDER=weknora`；生产配置仍须通过环境变量注入凭证，并保留 Provider 关闭时的受控降级能力。

## 5. 下一次开发的明确范围

Gold V2 数据导入、Phase 13A 工程评测与 Phase 10B Admin 控制台已交付。下一步并行推进 **Phase 13B 真实知识质量评测** 与 **原方案 Phase 2 的真实账号、安全凭证和试点成本边界**；两者都是校园试点前的必需验收项。

继续遵守原方案：WeKnora 优先、Adapter 隔离、学校配置集中管理。现阶段不增加通用 RAG 自研、复杂 ReAct、多高校产品化或重型基础设施。
